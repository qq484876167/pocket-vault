# PocketVault（口袋文件库）

Android 手机端的**本地隔离文件库**。导入的照片、视频、文档仍然存放在你自己的手机上，但落在应用的私有目录里——系统文件管理器和相册都看不到它们。应用内可以分类浏览、搜索、整理，并且直接看图、播视频、读 PDF、看 TXT 小说。

**零运行时权限，不联网，不上传，没有账号。** 清单里没有 `INTERNET` 权限（合并后的清单只有 AndroidX 自动添加的自签权限），因此技术上无法发起任何网络请求。卸载即清空。

## 功能

### 收纳与导入
- 首次进入引导导入，之后随时可加
- 支持**单个文件**与**整个文件夹**批量导入，并**保留原有目录层级**（SAF 树逐层遍历）
- 两种入库方式：复制，或**移动**（复制并入库成功后才删除源文件；系统相册选择器只授予读权限，因此该入口只能复制）
- 导入进度与结果可查（多少成功、多少因来源不允许删除而保留）

### 浏览与管理
- 底部五个入口：**文件库**（全部 / 最近 / 收藏 / 按类型）、**目录**、**搜索**、**回收站**、**设置**
- 类型分桶：图片 / 视频 / 音频 / 文档 / 压缩包 / 其他 / 文件夹
- 排序：名称（中文按**拼音**排，`java.text.Collator`）、大小、修改时间、导入时间，支持升降序
- 搜索：文件名匹配，LIKE 通配符已转义；在目录页点搜索图标可**只在当前目录及其所有子目录内搜索**，搜索页顶部会显示可一键清掉的「范围」标签（范围用路径前缀等值比较，区分大小写，不会串到 `某目录2/` 这类兄弟目录）
- 操作：新建文件夹、重命名、库内移动到任意目录、多选/全选、分享、用其他应用打开（FileProvider 单文件临时授权）、收藏（星标）
- **移动 / 复制 / 解压的目标位置**是一个逐层进入的目录浏览器（面包屑可跳回、返回键退一层、每行显示「N 项」子项数、顶部保留最近 5 条历史目标、可在里面直接新建文件夹并进入）；移动文件夹时它自己与其所有后代在导航过程中就被标灰，不用等点了才报错
- **回收站**：删除先进回收站并保留层级关系，可还原、可彻底删除，超过保留天数自动清理（默认 30 天，可调 1–365）
- **出口**：导出到手机公共目录（写 MediaStore，可选择是否让相册收录）；或**移出本应用**到用户指定的任意目录——复制后核对字节数一致才删除库内文件
- 设置页显示库内占用与剩余空间

### 应用内查看（不跳出、不装别的 App）
- **图片**：左右滑动翻页（同目录同类型按文件名顺序构成序列）+ 条漫式上下连续滚动两种模式；双指缩放、旋转、位置提示
- **视频**：应用内直接播放，解码交给系统 `MediaPlayer`，不额外引入播放器依赖
- **PDF**：`PdfRenderer` 逐页渲染；页位图 LRU 缓存容量随堆上限动态计算（`maxMemory()/8`，夹在 24–96 MB），预取 ±1 页
- 渲染/解码失败时把**异常类名与消息显示在界面上**，而不是无限转圈

### TXT / 小说阅读器
- **编码兼容**：自动识别 UTF-8 / GB18030 / Big5 / UTF-16LE / UTF-16BE（先看 BOM，再严格试 UTF-8，再按 U+FFFD 占比择优）；识别错了可在「Aa」里手动逐个切换并原地重载
- **自动分章**：`第X章/回/节/篇/话/卷`、序章/楔子/尾声/后记/前言/番外、`Chapter N`、`001.` 序号行、纯数字行；认不出任何标题时按固定大小切成「第 N 部分」，保证目录和上下章始终可用
- **目录 / 书签 / 全文搜索**：搜索结果能精确跳到命中的那一段；书签按「章 + 段落」存，可标记、跳转、删除
- **排版可调**：字号 13–32 sp、行距 1.3–2.4、页边距 8–40 dp、四套配色（纸白 / 羊皮 / 护眼 / 夜间），全部持久化
- **进度记忆**：按「章 + 章内段落」保存，因此换字号、换行距、改边距都不会让位置漂走
- **大文件不卡**：打开时只扫一遍建立索引，正文不驻留内存；读某一章时按字节区间 `seek` 定位再解码那一段。24 MB / 2000 章实测：建索引 0.6 s、取任意一章 < 1 ms、全文搜索 4 ms
- **阅读体验**：屏幕常亮、长按选中并复制文字、点屏幕上下区域翻一屏、左右滑切上下一章、顶栏底栏可一起隐去

### 压缩包
- **能在应用内解压的格式**：zip（以及 `jar` / `apk` / `cbz` 这类 zip 容器）、tar、tar.gz / tgz、tar.bz2 / tbz2 / tbz、tar.xz / txz、单独的 gz / bz2 / xz、7z。全部走流式读取，不把整包读进内存
- **rar / cbr 有意不支持**：UnRAR、junrar 的授权条款与本项目 GPL-3.0 冲突。遇到这类文件（以及 iso / zst / lz4 / cab 等）会明确说明原因，并给出**「用其他应用打开」**，不会只留一张空白卡片
- **单击压缩包**先弹操作菜单：解压到同名新文件夹 / 解压到当前文件夹 / 解压到指定目录 / 查看压缩包内容
- **多选里勾选压缩包**可直接批量解压，一个包失败不影响其余，结束时汇总「成功 N 个、失败 M 个（附原因）」
- **解压目标三选一**；「同名新文件夹」撞上已有目录时可选合并、改名成 `原名 (2)` 或取消；解压完能一键进入生成的那个文件夹，也能一键清理本次的半成品（走库删除链路，不留游离文件）
- **同名冲突**可选覆盖 / 保留两者（自动改名）/ 跳过，选一次对整包生效，结果里分别计数。冲突目标是**目录**时一律不覆盖，自动退化为改名
- **解压前先算空间**：给出「需要约 X，可用 Y」，明显不够时按钮直接禁用
- **加密包**：支持传统 **ZipCrypto**、**AES-256**、**头部加密的 7z**。密码是**真读 16 个字节**验证的——zip 的中央目录不加密，能列出文件名不代表密码对；「还没给密码」「密码不对」「包已损坏」是三种不同状态，各说各的话；密码错时输入框内容保留并把光标留下，改一个字符就能重试；留空当取消处理。**密码只存在本次会话的内存里**，不写盘、不进 SavedStateHandle，进程被杀后重新问一次
- **包内条目**可单独提取到库内、或就地预览（图片 / 文本）；目录行可展开折叠，长列表分页加载，不再有截断上限
- **zip-slip 防护覆盖所有格式**：包内条目名一律经清洗，绝对路径、盘符、`..` 越界、Windows 保留名所在的条目整条丢弃；符号链接与设备文件列得出来，但**绝不落盘**（链接能把写入指到库外）
- 把库内条目压缩成 zip，可设密码（AES-256），可选**存储 / 快速 / 标准 / 极限**四档，确认前显示「将打包 N 项 · 合计 X」
- 解压在应用前台执行，进度条按已写字节推进；界面上写明了**请保持应用在前台**（后台服务需要额外权限与通知，当前没做）

## 隔离是怎么做到的

| 手段 | 效果 |
|---|---|
| 默认根目录用应用内部私有目录 `/data/user/0/<包名>/files/vault` | SELinux 沙箱保证只有本应用能读；系统文件管理器走公共目录，进不来 |
| **不写 MediaStore**、不主动生成媒体记录，并放置 `.nomedia` 兜底 | 导入的照片**不会出现在系统相册** |
| Manifest 里不申请 `READ/WRITE_EXTERNAL_STORAGE`、不申请定位等任何运行时权限 | 装好即用，没有授权弹窗；只能读用户通过 SAF 主动选中的内容 |
| `allowBackup = false` + `dataExtractionRules` / `backup_rules` 显式排除索引库与 `vault_prefs.xml` | 换机、云备份不会把私密文件清单带走 |
| 对外分享走 `FileProvider`，只授予**单个文件**的临时 URI 权限 | 不给整目录权限，对方应用只读这一次 |
| 索引（Room）与文件同生命周期 | 卸载即全部清空 |

可选根目录 `getExternalFilesDir`（外部沙箱）保留在设置里，但**默认不推荐**：部分厂商 ROM 的特权文件管理器仍能浏览 `Android/data`。

## 技术栈

Kotlin 2.0.21 · Jetpack Compose（BOM 2024.12.01 / Material3）· ViewModel + StateFlow · Room 2.6.1（KSP）· Coil 2.7.0 · zip4j 2.11.5 · Apache Commons Compress 1.26.2 + `org.tukaani:xz` 1.10（tar / gz / bz2 / xz / 7z）· Storage Access Framework · `PdfRenderer` / `MediaPlayer`（系统自带）

`minSdk 29 / targetSdk 35 / compileSdk 35`，JDK 17，AGP 8.7.3。UI 文案为中文硬编码（尚未做 i18n 资源抽取）。

```

├── MainActivity.kt / AppGraph.kt        # 入口与手写依赖图（进程级 ioScope）
├── core/                                # 存储根目录、偏好设置、文件类型判定

├── ui/
│   ├── VaultApp.kt / Navigator.kt       # 导航与五个顶层目的地

└── util/                                # TextBook（编码 + 分章 + 字节寻址）、PdfDocument、FileBridge 等
```

## 构建与安装

```bash
./gradlew assembleDebug          # 产物：app/build/outputs/apk/debug/app-debug.apk
./gradlew assembleRelease lintDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

需要本地 Android SDK（platforms;android-35、build-tools;35.0.0），在 `local.properties` 里写 `sdk.dir=...`（该文件不入库）。

> 中国大陆网络提示：`repo1.maven.org` 常常不可达，`settings.gradle.kts` 已把腾讯云镜像与 `repo.maven.apache.org` 排在 `mavenCentral()` 之前；Gradle Wrapper 的 `distributionUrl` 同样指向镜像。把它改回"只有 `google()` + `mavenCentral()`"在某些网络下会 Sync 失败。

## 已知限制（有意不做）

- **没有静态加密**：文件在私有目录里是明文存放。加 Keystore/AES-GCM 会破坏流式预览与外部播放器接管，需要额外的解密到缓存管线
- 视频不支持外挂字幕（`VideoView` 能力所限）；音频没有应用内播放与后台锁屏控制（会明显增大包体，当前交给系统播放器）
- 不做"精确算字的真分页"（换字号要重排、图片与空行断页复杂），阅读用滚动 + 翻屏
- 不支持 rar / cbr（许可冲突，见上）；不支持 iso / zst / lz4 / cab 等在应用内解压。压缩包只读不解包外的位置——**解压一律落在库内**，要放到库外请用「移出本应用」
- 没有后台解压：服务与通知需要额外权限，当前改为在前台执行并在界面上提示「请保持应用在前台」
- 无书架管理、无多端同步
- 图片放大只保证"看原图"，没有做超分/多级重渲染管线
- 手势类改动（屏幕常亮、长按选中、退出后回位）与 PDF/图片渲染路径**尚未经真机验证**；欢迎带界面上的报错文字来开 issue

## 测试与验证方式

- **纯逻辑用可执行的断言验证**：`util/TextBook.kt` 不依赖 Android，可以单独编成 JVM 程序跑 42 项断言——编码识别（UTF-8 / GB18030 / Big5 / UTF-16LE+BE / emoji / CRLF / 纯 ASCII / BOM）、字节寻址的正确性（跨 256 KB 数据块的行、落在块内的章节边界、BOM 偏移、整本无换行的强制分段、末行无换行、空文件、奇数尾字节）、搜索命中段落号可精确回溯、以及 24 MB 文件的性能。另有压力用例：每行都像标题的 1.2 MB 文件（60,000 章）搜索 78 ms、全书逐章取段 867 ms 不退化；500 个相邻章节标题不会产生任何 0 长度区间。
- **密码判定表也在 JVM 上跑真包**：`scratch/pstub/PwProbe.kt` 用 7-Zip 命令行做出的 `zipcrypto.zip` / `aes256.zip` / `mixed.zip`（部分条目加密）/ `header7z.7z`（头部加密）/ `content7z.7z` / `broken.zip` 逐个断言 `access` 结论，并核对解出的字节内容；样本由 `scratch/pwbox` 提供
- **构建层面**：`assembleDebug` / `assembleRelease` / `lintDebug` 全绿，lint **0 errors**；发布前对 APK 做 zip 完整性与 dex 符号核对，确认改动确实进了产物
- **归档层同样脱离 Android 跑真归档**：`data/ArchiveReader.kt` + `core/PathRules.kt` 可编成纯 JVM 程序，对 13 个真实包（zip / tar / tar.gz / tgz / tar.bz2 / tar.xz / 7z / 单文件 gz·bz2·xz / 恶意 tar / 加密 zip / rar）逐个比对**每个条目落地后的 SHA-256**，与 Python 独立生成的参考清单 26 项一致；另断言恶意 tar 的 `../../evil.txt`、`/etc/passwd`、`dir/../../up.txt` 被整条丢弃且包外不出现文件、加密包在无密码时报告「需要密码」、错密码抛专门异常、RAR 走「不支持 + 原因」；整包解压与「单条目随机读取」（顺序格式靠重扫）两条路径的结果逐条一致
- **未做**：UI 自动化测试与云真机矩阵；厂商 ROM 的隔离行为差异（MIUI / ColorOS / 鸿蒙对 `Android/data` 的处理）依赖用户实测反馈
